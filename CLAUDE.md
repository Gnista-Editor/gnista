# Ember

A Rust editor that works the way Emacs works. Ember is a placeholder name. The original vision is in [docs/brief.md](docs/brief.md), but [ADR 0002](docs/adr/0002-start-simple.md) overrides it: start simple, no sandbox, AI starts as tool calls to commands, and org mode is a package rather than part of the core. Extensions are TypeScript on QuickJS ([ADR 0003](docs/adr/0003-typescript-on-quickjs.md)). The graphical front end is egui with ArtCraft's look ([ADR 0004](docs/adr/0004-egui-front-end.md)). Variables, hooks and modes follow [ADR 0006](docs/adr/0006-variables-hooks-and-modes.md), text properties, faces and display rows [ADR 0007](docs/adr/0007-text-properties-faces-and-display-rows.md), highlighting [ADR 0008](docs/adr/0008-tree-sitter-highlighting.md), windows [ADR 0009](docs/adr/0009-windows.md), the mouse and line wrapping [ADR 0010](docs/adr/0010-mouse-and-line-wrapping.md), search and the minibuffer [ADR 0011](docs/adr/0011-search-and-the-minibuffer.md), org mode and fontifying [ADR 0012](docs/adr/0012-org-mode.md), and porting Org's Lisp closely, with the change hooks, markers and undo that needs, [ADR 0013](docs/adr/0013-following-org-closely.md), the agenda and capture [ADR 0016](docs/adr/0016-org-agenda-and-capture.md), files and saving [ADR 0018](docs/adr/0018-files-and-saving.md), the agent [ADR 0019](docs/adr/0019-agent-buffer.md), and frames [ADR 0017](docs/adr/0017-frames.md). Ember is GPL-3.0-or-later ([ADR 0014](docs/adr/0014-gpl.md)); [docs/licensing.md](docs/licensing.md) records which code is derived from Emacs and the alternatives.

The plan for growing Ember towards Emacs parity is in [docs/plan.md](docs/plan.md).

## Current state

A working editor, in a terminal (`ember`) or a window (`ember-gui`): buffers, windows (`C-x 2`, `C-x 3`, `C-x o`, `C-x 0`, `C-x 1`, resizing with `C-x ^`, `C-x }`, `C-x {`, `C-x +` and the mouse, asking about each file on `C-x C-c`), questions (`yes-or-no-p`, `y-or-n-p`) and timers, an agent (`M-x agent`: talk to Claude in an Org buffer while it calls commands as tools, asking before it writes files or quits, each turn one undo step), Emacs movement and editing keys, the active region with shift selection (transient-mark-mode and shift-select-mode, both on), prefix arguments (`C-u`, `M-<digit>`, `C--`), mouse wheel and trackpad scrolling of the window under the pointer, clicks, drags, double and triple clicks and shift-click as Emacs mouse keys (`<mouse-1>`, `<drag-mouse-1>`, `<double-mouse-1>`), long lines continued by default, `truncate-lines` and `visual-line-mode`, the kill ring with `M-y`, the mark ring (`C-u C-SPC`), undo as in Emacs (undoable, with `undo-redo`), keyboard macros (`F3`, `F4`, `C-x (`, `C-x )`, `C-x e`), repeat (`C-x z`), documented variables with buffer-local values (`C-h v`), hooks, major and minor modes with their own keymaps (`C-h m`), choosing the major mode from the file name, `text-mode`, `overwrite-mode` and `delete-selection-mode`, text properties, overlays and faces (`describe-face`), invisible text and folding (`outline-mode`, `outline-minor-mode`), org mode (`org-mode`: folding, structure editing, TODO states, tags, checkboxes, timestamps, links, tables, properties (`C-c C-x p`), refiling (`C-c C-w`), narrowing (`C-x n s`), the week agenda and TODO list (`org-agenda`), and capture (`org-capture`)), narrowing (`C-x n n`, `C-x n w`), tree-sitter highlighting (`rust-ts-mode`, `js-ts-mode`, TypeScript extensions: `init.ts` defines commands and key bindings, `M-x load-file` reloads it, and `M-:` evaluates an expression.

## Layout

- `crates/ember-core`: all editor state and commands. No UI or script dependencies. `properties.rs` holds text properties and overlays, `faces.rs` faces and the colour palette both front ends use, `rows.rs` turns a window into display rows: styled segments with hidden text left out, `syntax.rs` keeps each buffer's tree-sitter tree and turns its captures into faces for those rows, and `search.rs` translates Emacs regexps and searches, `completion.rs` holds the completion styles, `window.rs` holds the window tree, which each front end lays out in its own units before telling the core each window's size, `coding.rs` reads and writes codings (UTF-8, Latin-1, DOS and Mac line ends), `fileio.rs` reads and writes visited files, with backups, auto-saving and reverting, `questions.rs` lets a command ask a question and go on with the answer, `timers.rs` runs timers and auto-saves when idle (front ends call `Editor::run_timers` when `next_timer_in` says), and `fontify.rs` is jit-lock: `Editor::redisplay`, which front ends call before drawing, runs `jit-lock-functions` on the lines about to show that are not fontified yet. Tests that look at faces call `redisplay` too. Front ends draw rows, through `display::row_glyphs`, never buffer lines. `Editor` is driven by `handle_key`, `press("C-x C-f")`, `type_text`, or `call(name, args)` for code and tool calls.
- `crates/ember-script`: the QuickJS runtime and the `ember` API for scripts. `config.rs` finds the config directory and loads `init.ts` for both front ends. `strip.rs` erases TypeScript types, `prelude.js` builds the `ember` global from native functions, `types.rs` generates `ember.d.ts`.
- `crates/ember`: the terminal binary. `ui.rs` draws, `main.rs` reads keys.
- `crates/ember-agent`: Ember's agent, an extension the front ends install through `config::setup_with` ([ADR 0019](docs/adr/0019-agent-buffer.md)). `api.rs` streams the Claude Messages API over HTTP on a thread of its own (key from `ANTHROPIC_API_KEY` or the keychain); `lib.rs` runs the conversation from a timer on the editor's thread, writes it into `*agent*` (`agent-mode`, from its own `agent.ts`, built on Org) and runs tool calls, the MCP server's, in the user's window. While the agent acts, the core's `Editor::check_permission` stops writing files, discarding unsaved work, quitting and running code until the user approves. Tests use a scripted model; `tests/live.rs` talks to the real API when run with `--ignored`.
- `crates/ember-mcp`: Ember as an MCP server ([ADR 0015](docs/adr/0015-mcp-server.md)). `lib.rs` answers MCP messages with tools over the command registry (`list_commands`, `describe_command`, `call_command`, `press_keys`, `read_buffer`, `screen`, ...); `socket.rs` is the local socket the GUI listens on so `ember-mcp` can drive the editor the user sees, or the binary runs a headless editor of its own.
- `crates/ember-gui`: the egui binary. `app.rs` draws and scrolls smoothly: whole lines go to the core as `<wheel-up>`/`<wheel-down>` keys (bound to `mwheel-scroll`, so rebindable), and only the leftover fraction of a line is kept in the GUI as a pixel offset. `keys.rs` translates egui key events into keys and `app.rs` turns pointer events into mouse keys after hit-testing the windows, `theme.rs` holds the colour tokens and fonts. Drawing code takes colours from `Tokens`, never literals.
- `packages/`: TypeScript packages that ship with Ember, as Emacs ships its preloaded Lisp. Each follows the Emacs Lisp file of the same name: `simple.ts` (prefix arguments, `yank-pop`, `fundamental-mode`, `overwrite-mode`, `visual-line-mode`, `toggle-truncate-lines`), `files.ts` (`normal-mode`, `auto-mode-alist`, `save-buffer`, `write-file`, `revert-buffer`, `recover-file`, `save-some-buffers`, `save-buffers-kill-terminal`, `auto-revert-mode`), `text-mode.ts`, `delsel.ts` (`delete-selection-mode`), `help.ts` (`help-mode`, `C-h v`, `C-h m`, `describe-face`), `outline.ts` (`outline-mode`, `outline-minor-mode`, folding with invisible overlays), `prog-mode.ts`, `treesit-modes.ts` (the tree-sitter major modes), `repeat.ts`, `kmacro.ts`, `window.ts`, `mouse.ts`, `isearch.ts`, `replace.ts`, `org.ts` (`org-mode`: org.el with the parts of org-list.el and ol.el it needs) and `org-table.ts`. A mode that styles text adds a function to `jit-lock-functions`, as `outline.ts` and `org.ts` do, and a mode can remap commands with `ember.remapCommand`, as org remaps typing for tables. Modal commands such as isearch use `ember.setOverridingMap`, `ember.setKeymapDefault` and `ember.unreadKeys`, as Emacs's Lisp uses `overriding-terminal-local-map`, `[t]` bindings and `unread-command-events`. Define modes with `ember.defineMajorMode` and `ember.defineMinorMode`, which are in the prelude. The editor primitives they use (kill ring rotation, the last repeatable command, recording and replaying macros) are in ember-core. They load at startup, before init.ts, even with `-q`; the list is `PACKAGES` in `ember-script/src/lib.rs`. `packages/ember.d.ts` is generated: after changing commands or the script API, run `UPDATE_TYPES=1 cargo test -p ember-script`, then `tsc -p packages` to type-check the packages.
- `examples/init.ts`: a sample config.

Variables, hooks, named keymaps and the minor mode registry are in `ember-core` (`variables.rs`, `modes.rs`); a Rust command reads a variable with `ed.variable(name)`. Commands are defined once with named, typed parameters (`Command::new(...).param(...)`). A command reads its prefix argument with `ed.prefix_numeric()` (a count, 1 by default) or `ed.current_prefix_arg()` (the raw form, to tell plain C-u from a number), as Emacs's interactive "p" and "P" do. Movement commands are marked `.shift_select()`, like Emacs's `^` interactive spec: a shifted key with no binding of its own runs the unshifted key's command and selects as it moves. Interactive use prompts for each parameter in the minibuffer; `Editor::call` takes them directly. Keep it that way: it is what lets scripts, and later the agent, call commands as tools.

Adding a function to the script API means three changes: the native function in `ember-script/src/lib.rs`, its wrapper in `prelude.js`, and its declaration in `types.rs`. Prefer making new behaviour a command, which needs none of these.

## Running

```bash
cargo run -p ember -- some-file.txt
cargo run -p ember-gui -- some-file.txt
cargo test
cargo clippy --all-targets
```

- Ember loads `init.ts` from `$EMBER_CONFIG_DIR`, else `$XDG_CONFIG_HOME/ember`, else `~/.config/ember`. `-q` skips it. At startup Ember writes `ember.d.ts` there, and `tsconfig.json` if missing, so `tsc -p ~/.config/ember` type-checks the config.
- `cargo run -p ember -- --print-types` prints the generated declarations.
- `claude mcp add ember -- target/release/ember-mcp` (after `cargo build --release -p ember-mcp`) lets Claude Code use Ember: the open GUI if there is one, else a headless editor.
- The GUI uses Geist Mono and Inter if they are installed, and egui's built-in fonts otherwise. Without Geist Mono Bold, bold text is drawn twice, slightly apart.
- GUI snapshots live in `crates/ember-gui/tests/snapshots/`. After an intended visual change, run `UPDATE_SNAPSHOTS=1 cargo test -p ember-gui`, then look at the new images before committing them.
- `tests/emacs/` compares Ember with real GNU Emacs on recorded cases (see its README). A case can answer the prompts its keys open (`answers`), compare windows (`windows`), seem to visit a file (`visit`), or visit real ones (`files`, `find`, `disk` for a change on disk at `<f33>`), comparing what the directory holds afterwards. After adding or changing cases, record them with `emacs -Q --batch -l tests/emacs/record.el`. `known-gaps.txt` lists where Ember does not match yet. `tests/emacs/README.md` also says how to run the org-mode fuzzer, which finds new differences from Emacs on random documents and keys.
- `crates/ember-script/tests/bench.rs` times a 50,000-line Org file and a 100 MB text file; [docs/performance.md](docs/performance.md) says how to run it and records the results.
- On macOS, `.cargo/config.toml` links with `/usr/bin/cc`, because the Nix `cc` on PATH cannot find the SDK (`library not found for -liconv`).

## Conventions

- Match Emacs names, keys and messages unless there is a reason not to. When behaviour should match Emacs, add an oracle case in `tests/emacs/cases/` rather than guessing what Emacs does.
- Commands Emacs writes in Lisp are written in TypeScript ([ADR 0005](docs/adr/0005-rust-core-typescript-commands.md)); Rust is for what Emacs does in C.
- Every feature lands with tests. Behaviour a user sees gets a headless test driven by key sequences: in `crates/ember-core/tests/` for the core, `crates/ember-script/tests/` for scripts, and a snapshot in `crates/ember-gui/tests/` for anything drawn differently.
- Decisions go in `docs/adr/NNNN-short-title.md` (template in `docs/adr/0000-template.md`), naming any new dependency and its purpose.
- Never commit API keys or real personal org files.

## Ask the human before

- changing the extension language or its runtime;
- adding a network dependency to `ember-core`;
- relaxing a safety default.
