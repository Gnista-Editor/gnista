# Ember

A Rust editor that works the way Emacs works. Ember is a placeholder name. The original vision is in [docs/brief.md](docs/brief.md), but [ADR 0002](docs/adr/0002-start-simple.md) overrides it: start simple, no sandbox, AI starts as tool calls to commands, and org mode is a package rather than part of the core. Extensions are TypeScript on QuickJS ([ADR 0003](docs/adr/0003-typescript-on-quickjs.md)). The graphical front end is egui with ArtCraft's look ([ADR 0004](docs/adr/0004-egui-front-end.md)). ## Layout

- `crates/ember-core`: all editor state and commands. No UI or script dependencies. `properties.rs` holds text properties and overlays, `indirect.rs` makes indirect buffers, each keeping a copy of the text that the editor keeps the same after every change, with one undo history moving to whichever buffer records a change, `textprop.rs` searches them as textprop.c does and finds fields (`field-beginning`, `constrain-to-field`, which C-a and the word commands obey), `faces.rs` faces, with Emacs's attributes and anonymous faces, and the colour palette both front ends use, the colour names Emacs knows in `colors_data.rs`, generated by `tests/emacs/colors.el`, `rows.rs` turns a window into display rows: styled segments with hidden text left out, overlay strings and `display` strings shown as Emacs shows them, and what each row shows in its margins and fringes, `image.rs` is image.c: image specs as list values, checked as `valid_image_p` does, and the image cache, which reads an image's size from its header (the `image` crate for PNG, JPEG and GIF, `resvg` for SVG) and works out the size it shows at from `:scale`, `:width`, `:max-width` and the rest; a display spec's image is a segment with an `ImageGlyph`, off the grid, whose row is as tall as its ascent and descent say, shown only when the front end's `TextMetrics::images` says, the text otherwise; pixels are decoded only when a front end draws them (`Editor::image_rgba`), `bidi.rs` is the bidi algorithm as Emacs's bidi.c resolves it, on Emacs's tables in `bidi_data.rs`, generated by `tests/emacs/bidi-data.el`, and `bidi_display.rs` reorders a line's row with it before the row is broken into screen rows, a right-to-left row turned around to run left to right and laid out from the window's right edge (`Row::right_to_left`, `Editor::row_offset_in`), with the bidi primitives, buffers that never held right-to-left text (`Buffer::has_rtl`) skipping it, `fringe.rs` the fringe bitmaps (`define-fringe-bitmap`) and which a row shows (`Editor::window_fringes`, as fringe.c's `update_window_fringes`), when the front end's metrics say its frames have fringes, and the overlay arrow, written over its row where they do not, `font.rs` fonts as values (`Value::Font`: specs, entities and open fonts, with their XLFD names), the questions about them answered by the front end's `TextMetrics` (`font_metrics`, `font_families`, `has_glyph`), `syntax.rs` keeps each buffer's tree-sitter parsers and turns the major mode's captures into faces for those rows, `treesitfns.rs` is treesit.c's primitives: parsers and nodes as values (`Value::Treesit`), a node held as its path from the root and out of date once its tree is parsed again, and queries with Emacs's predicates, `regexp.rs` is Emacs's regexp engine, as regex-emacs.c: Emacs's syntax parsed exactly and matched by a backtracking machine over the buffer, with its syntax table for `\w`, `\sC`, `\_<` and `[:space:]`, back-references and `\=`, and `search.rs` searches with it, literal searches with the `regex` crate, `chartab_data.rs` holds Emacs's character tables, generated by `tests/emacs/unicode.el` (general categories, scripts, the standard syntax table, case and categories), which regexps and the standard syntax table read, `completion.rs` holds the completion styles, as minibuffer.el's patterns, `minibuffer.rs` reading from the minibuffer (` *Minibuf-1*`, a buffer in the buffer list, current while a prompt is open) partway through a command (`completing-read`, `read-file-name`), the sorted completions, and the rows the echo area shows (`minibuffer_rows`), with the strings of the overlays icomplete draws in, `syntax_table.rs` holds syntax tables, as Emacs's syntax.c, and the scanners on them (`scan-lists`, `forward-comment`, `parse-partial-sexp`), `symbols.rs` is the symbol table: each name's variable, a hook's functions, its function cell (a function, a command, or an alias) and its property list, and the advice on its function, `advice-add`'s, which every call by name goes through, `keymap.rs` holds keymaps, which are values (`Value::Keymap`): prefix maps are shared, a keymap's name such as `ctl-x-4-map` is a variable holding it, and a child's prefix maps merge with its parent's, `modeline.rs` formats each window's `mode-line-format` at redisplay, as Emacs's xdisp.c, into segments front ends draw (`Editor::mode_line`), and its `header-line-format` into the header line (`Editor::header_line`), which front ends leave a line for when `Editor::window_wants_header_line` says, `layout.rs` lays rows out as Emacs's redisplay does, with a front end's `TextMetrics` (cells for the terminal and headless editors, egui's fonts for the GUI): each glyph's width and each row's height, rows of the default font's size in a fixed-width font on the grid as before, and the position functions on them, `window.rs` holds the window tree, which each front end lays out in its own units before telling the core each window's size, `insdel.rs` is insdel.c: every change the editor makes goes through `Editor::insert`, `delete_region` and their kin, which refuse read-only buffers and text unless `inhibit-read-only` says otherwise and run `before-change-functions` and `after-change-functions`; `Buffer`'s raw edits are crate-internal. `coding.rs` holds the coding systems, Emacs's 55 commonest under its names (UTF-8, UTF-16, the ISO 8859 and Windows sets, Shift_JIS, EUC, ISO-2022, GBK, Big5) on `encoding_rs`'s tables, with line ends, detection and raw bytes (U+10FF80 to U+10FFFF, shown as `\351`), `charset.rs` the charsets with Emacs's code points, `codingfns.rs` the primitives scripts call (`encode-coding-string`, `detect-coding-region`, `encode-char`), `fileio.rs` reads and writes visited files, with backups, auto-saving and reverting, `fileops.rs` copies, renames and deletes files (to the trash), makes directories and lists them, `filefns.rs` is the file primitives Lisp calls (`insert-file-contents`, `write-region`, the `file-*-p` predicates), each offered first to a handler in `file-name-handler-alist`, `filelock.rs` makes and checks lock files (`.#name`), `casefiddle.rs` changes case as Emacs's casefiddle.c does, with Unicode's special casings and final sigma, `chartab.rs` holds char-tables, which are values (`Value::CharTable`), and `casetab.rs` and `category.rs` the case and category tables built on them, which each buffer has, the standard ones answered by the generated tables while unchanged, `questions.rs` lets a command ask a question and go on with the answer, `select.rs` links the kill ring to the system clipboard a front end supplies, as Emacs's `select-enable-clipboard` does, `keyboard.rs` is keyboard.c's primitives: reading a key partway through a command (`read-key`, `read-key-sequence`), `this-command-keys`, `recent-keys`, and recursive edits, `process.rs` runs programs alongside the editor, as Emacs's process.c, on a pseudo-terminal by default or on pipes, and network connections and servers over TCP and local sockets, each with its coding systems, their output taken in when front ends run timers, `quit.rs` is `quit-flag`: a flag per editor that any thread sets through a `QuitHandle`, checked at safe points by `Editor::maybe_quit` (the regexp matcher, `scan-lists`, every call from a script) unless `inhibit-quit` is set, `specbind.rs` the binding stack, as Emacs's specpdl, which `letBind`, `withCurrentBuffer`, `saveExcursion` and `saveRestriction` push to, so a script stopped without unwinding has its bindings restored, `timers.rs` runs timers and auto-saves when idle (front ends call `Editor::run_timers` when `next_timer_in` says), and `fontify.rs` is jit-lock: `Editor::redisplay`, which front ends call before drawing, runs `jit-lock-functions` on the lines about to show that are not fontified yet. Tests that look at faces call `redisplay` too. Front ends draw rows, never buffer lines, from `frame_description.rs`: after redisplay `Editor::describe_frame` describes a frame as plain data, each window's rows with their glyphs (`display::row_glyphs`), styles and geometry (a right-to-left row's offset, the row point shows on), its fringes, line numbers, mode line and header line, the echo area or minibuffer, and images' pixels, and front ends draw only from it, never asking the editor while they draw, so the editor can run on a thread of its own; laying windows out and hit-testing the mouse are input, which still go to the editor. `Editor` is driven by `handle_key`, `press("C-x C-f")`, `type_text`, or `call(name, args)` for code and tool calls.
- `crates/ember-script`: the QuickJS runtime and the `ember` API for scripts. `config.rs` finds the config directory and loads `init.ts` for both front ends. `strip.rs` erases TypeScript types and puts a check for quitting at the start of every loop's body (the work is in `strip_js.rs`, which `build.rs` also runs on `packages/` when Ember is built, so startup loads them ready to run), `prelude.js` builds the `ember` global from native functions, `types.rs` generates `ember.d.ts`. `images.rs` holds image.c's primitives for scripts (`imagep`, `imageSize`, `imageFlush`, ...).
- `crates/ember`: the terminal binary. `ui.rs` draws, `main.rs` reads keys.
- `crates/ember-agent`: Ember's agent, an extension the front ends install through `config::setup_with` ([ADR 0019](docs/adr/0019-agent-buffer.md)). `api.rs` streams the Claude Messages API over HTTP on a thread of its own (key from `ANTHROPIC_API_KEY` or the keychain); `lib.rs` runs the conversation from a timer on the editor's thread, writes it into `*agent*` (`agent-mode`, from its own `agent.ts`, built on Org) and runs tool calls, the MCP server's, in the user's window. While the agent acts, the core's `Editor::check_permission` stops writing files, discarding unsaved work, quitting and running code until the user approves. Tests use a scripted model; `tests/live.rs` talks to the real API when run with `--ignored`.
- `crates/ember-mcp`: Ember as an MCP server ([ADR 0015](docs/adr/0015-mcp-server.md)). `lib.rs` answers MCP messages with tools over the command registry (`list_commands`, `describe_command`, `call_command`, `press_keys`, `read_buffer`, `screen`, ...); `socket.rs` is the local socket the GUI listens on so `ember-mcp` can drive the editor the user sees, or the binary runs a headless editor of its own.
- `crates/ember-gui`: the egui binary. `app.rs` draws and scrolls smoothly: whole lines go to the core as `<wheel-up>`/`<wheel-down>` keys (bound to `mwheel-scroll`, so rebindable), and only the leftover fraction of a line is kept in the GUI as a pixel offset. `keys.rs` translates egui key events into keys and `app.rs` turns pointer events into mouse keys after hit-testing the windows, `theme.rs` holds the colour tokens and fonts, with fallbacks for CJK, emoji, Hebrew and Arabic, `metrics.rs` the core's `TextMetrics` from egui's fonts, with the system's families from fontique, `image.rs` draws images from textures of the pixels the core decodes, kept per image id, `clipboard.rs` the system clipboard (⌘C, ⌘X and ⌘V copy, cut and yank through the kill ring, as on Emacs's Mac port), and `modeline.rs` the GUI's own default `mode-line-format`, set before init.ts runs, whose faces `draw_mode_line` maps to tokens. Drawing code takes colours from `Tokens`, never literals.
- `packages/`: TypeScript packages that ship with Ember, as Emacs ships its preloaded Lisp. Each follows the Emacs Lisp file of the same name: `misc.ts` (`duplicate-dwim`, `copy-from-above-command`), `page.ts`, `iso-transl.ts` (`C-x 8`, its table generated by `tests/emacs/iso-transl.el`), A major mode's syntax table is NAME-syntax-table, built on its parent's, with the entries its `syntax` option gives, as text-mode.ts and org.ts set theirs. Packages share code by importing it from another package or through the `ember` API, never by copying: Emacs's primitives are there (`charAfter`, `currentIndentation`, `indentTo`, `indentLineTo`, `skipCharsForward`, `saveExcursion`, `syntaxPpss`), and a function a variable names, as `next-error-function`, is made with `ember.defun` and called with `ember.funcall`. A package changes another's function or command with `ember.adviceAdd`, as Lisp uses `advice-add`, rather than redefining it. Scripts keep positions across edits with markers (`ember.makeMarker`, freed with `ember.deleteMarker`), and take back trial edits with `ember.prepareChangeGroup` and `cancelChangeGroup`, as elec-pair.ts does. Text properties a script puts are undone and modify the buffer, as in Emacs; ones that only style text, outside jit-lock, go inside `ember.withSilentModifications`, as comint.ts and compile.ts do. Scripts start programs with `ember.makeProcess`, which asks the agent's permission, and run one to the end with `ember.callProcess`; `ember.afterPrompts` runs code once the questions a command opened are answered. A mode sets `indent-line-function`, `comment-start` and its syntax table for TAB, `M-;` and the sexp commands, as treesit-modes.ts does. A mode that styles text adds a function to `jit-lock-functions`, as `outline.ts` and `org.ts` do, and a mode can remap commands with `ember.remapCommand`, as org remaps typing for tables. Modal commands such as isearch use `ember.setOverridingMap`, `ember.setKeymapDefault` and `ember.unreadKeys`, as Emacs's Lisp uses `overriding-terminal-local-map`, `[t]` bindings and `unread-command-events`. Define modes with `ember.defineMajorMode` and `ember.defineMinorMode`, which are in the prelude. The editor primitives they use (kill ring rotation, the last repeatable command, recording and replaying macros) are in ember-core. They load at startup, before init.ts, even with `-q`; the list is `PACKAGES` in `ember-script/src/lib.rs`. Each package is an ES module named after its Emacs feature and imports others by that name, as Lisp files `require` each other (`import { truthy, forwardLine } from "subr"`): `subr.ts` holds what subr.el does, and `org-macs.ts` what Org's files share. A package that fails to load is logged and the rest still load. `packages/ember.d.ts` is generated: after changing commands or the script API, run `UPDATE_TYPES=1 cargo test -p ember-script`, then `tsc -p packages` to type-check the packages.
- `examples/init.ts`: a sample config.

Variables, hooks, named keymaps and the minor mode registry are in `ember-core` (`variables.rs`, `modes.rs`); a Rust command reads a variable with `ed.variable(name)`. A value can be a function (`Value::Function`), as a lambda in Lisp, and `Editor::defun`/`funcall` are the symbols' function cells: a variable such as `indent-line-function` holds a function or a name, and `ed.funcall` calls either. Commands are defined once with named, typed parameters (`Command::new(...).param(...)`); a parameter's prompt, starting input and collection to complete against can be worked out from the arguments read before it, as Emacs's interactive specs are code. Code in the middle of a command can also prompt, with `ember.completingRead`, `readFileName`, `readString`, `yOrNP` and the rest, read keys with `ember.readKey` and `readKeySequence`, or edit recursively with `ember.recursiveEdit`: make `run` async and `await` the answer, as project.ts does, which keeps the command's buffer and prefix argument and unwinds on `C-g` with `quit`; the older callback form is for code not yet moved. A command reads its prefix argument with `ed.prefix_numeric()` (a count, 1 by default) or `ed.current_prefix_arg()` (the raw form, to tell plain C-u from a number), as Emacs's interactive "p" and "P" do. A script command declares it instead, as a parameter of kind `count` or `prefix`, and point and the region as `point`, `region-beginning` and `region-end`: the editor fills these without asking, and code passes numbers, `ember.call("forward-paragraph", 2)`, or leaves a count out. Movement commands are marked `.shift_select()`, like Emacs's `^` interactive spec: a shifted key with no binding of its own runs the unshifted key's command and selects as it moves. Interactive use prompts for each parameter in the minibuffer; `Editor::call` takes them directly. Keep it that way: it is what lets scripts, and later the agent, call commands as tools.

Adding a function to the script API means three changes: the native function in `ember-script/src/lib.rs`, its wrapper in `prelude.js`, and its declaration in `types.rs`. Prefer making new behaviour a command, which needs none of these. Name it after the Emacs function it stands for, kebab-case as camelCase and `-p` as `P` (`buffer-live-p` is `bufferLiveP`, `skip-chars-forward` is `skipCharsForward`), returning `undefined` where Emacs returns nil; a few older names differ (`fileExists`, `isHook`, `isLocalVariable`). `the_api_defined_is_the_api_declared` in `tests/scripts.rs` fails if the prelude and `types.rs` disagree.

## Running

```bash
cargo run -p ember -- some-file.txt
cargo run -p ember-gui -- some-file.txt
cargo test
cargo clippy --all-targets
```

- Ember loads `init.ts` from `$EMBER_CONFIG_DIR`, else `$XDG_CONFIG_HOME/ember`, else `~/.config/ember`. `-q` skips it. At startup Ember writes `ember.d.ts` there, and `tsconfig.json` if missing, so `tsc -p ~/.config/ember` type-checks the config.
- `cargo run -p ember -- --print-types` prints the generated declarations.
- `claude mcp add ember -- target/release/ember-mcp` (after `cargo build --release -p ember-mcp`) lets Claude Code use Ember: the open GUI if there is one, else a headless editor.
- The GUI uses Geist Mono and Inter if they are installed, and egui's built-in fonts otherwise. Without Geist Mono Bold, bold text is drawn twice, slightly apart.
- GUI snapshots live in `crates/ember-gui/tests/snapshots/`. After an intended visual change, run `UPDATE_SNAPSHOTS=1 cargo test -p ember-gui`, then look at the new images before committing them.
- `tests/emacs/` compares Ember with real GNU Emacs on recorded cases (see its README). A case can answer the prompts its keys open (`answers`), compare windows (`windows`), seem to visit a file (`visit`), or visit real ones (`files`, `find`, `disk` for a change on disk at `<f33>`), comparing what the directory holds afterwards, directories (`sub/`) included, and set buffer-local variables first (`vars`). A case left in a Dired buffer is compared as each line's mark and file name, as sizes and dates differ between runs. `EMBER_ORACLE_ONLY=dired` compares, or records, only the case files whose names have it. After adding or changing cases, record them with `emacs -Q --batch -l tests/emacs/record.el`. `known-gaps.txt` lists where Ember does not match yet. `tests/emacs/README.md` also says how to run the org-mode fuzzer, which finds new differences from Emacs on random documents and keys, and the icomplete oracle in `tests/emacs/icomplete/`, which drives an interactive Emacs on a pseudo-terminal because batch Emacs cannot type into the minibuffer, and the bidi oracle in `tests/emacs/bidi/`, which reads an interactive Emacs's screen through tmux, as batch Emacs has no window to reorder text for.
- `crates/ember-script/tests/bench.rs` times a 50,000-line Org file and a 100 MB text file; [docs/performance.md](docs/performance.md) says how to run it and records the results. The aim is to be faster than Emacs everywhere; [docs/optimisation.md](docs/optimisation.md) lists where Ember is slower than it could be and what would help, each with how it was measured.
- On macOS, `.cargo/config.toml` links with `/usr/bin/cc`, because the Nix `cc` on PATH cannot find the SDK (`library not found for -liconv`).

## Conventions

- Match Emacs names, keys and messages unless there is a reason not to. When behaviour should match Emacs, add an oracle case in `tests/emacs/cases/` rather than guessing what Emacs does. Ideas for doing better than Emacs or Org go in [docs/departures.md](docs/departures.md), for when the base editor is stable, not into the code now. Where Ember behaves differently from Emacs today, deliberately or not yet fixed, is listed in [docs/differences.md](docs/differences.md): add a difference there when one is found or made.
- Regexps that are data (in variables, options, or from users) are Emacs regexps, matched with `ember.emacsRegexp`, `lookingAt`, `reSearchForward` and `matchString`; JavaScript regexps are fine inside a package's own code. Errors are signalled with a condition (`ember.signal`, `userError`) and caught by condition (`ember.conditionCase`), not by their message.
- Commands Emacs writes in Lisp are written in TypeScript ([ADR 0005](docs/adr/0005-rust-core-typescript-commands.md)); Rust is for what Emacs does in C.
- Every feature lands with tests. Behaviour a user sees gets a headless test driven by key sequences: in `crates/ember-core/tests/` for the core, `crates/ember-script/tests/` for scripts, and a snapshot in `crates/ember-gui/tests/` for anything drawn differently.
- Decisions go in `docs/adr/NNNN-short-title.md` (template in `docs/adr/0000-template.md`), naming any new dependency and its purpose.
- Never commit API keys or real personal org files.

## Ask the human before

- changing the extension language or its runtime;
- adding a network dependency to `ember-core`;
- relaxing a safety default.
